# 宜居城市数据爬取项目

## 一、项目背景与目标

### 1.1 项目背景
当前"宜居城市榜"系统有 298 个城市数据，但存在以下数据缺失：
- **城市图片**: 0 张（100%缺失）
- **用户评价**: 0 条（100%缺失）
- **人口数据**: 0 个城市（100%缺失）
- **租金数据**: 仅 153/298 城市有数据（49%缺失）
- **气候描述**: 112/298 缺失（38%缺失）

### 1.2 项目目标
通过数据爬取，丰富城市数据，提升用户体验：

| 目标 | 指标 | 优先级 |
|-----|------|-------|
| 城市图片 | 每城市 3-5 张风景图 | P0 |
| 用户评价 | 每城市 5-20 条真实评价 | P0 |
| 基础数据 | 人口、GDP、面积覆盖率 > 90% | P1 |
| 租金数据 | 覆盖率 > 95% | P1 |
| 房价数据 | 覆盖率 > 80% | P2 |
| 气候数据 | 覆盖率 100% | P2 |

---

## 二、数据需求分析

### 2.1 城市图片数据

**需求描述**：
- 每个城市 3-5 张高质量图片
- 图片类型：城市风景、地标建筑、生活场景、自然风光
- 图片尺寸：宽度 >= 800px，支持响应式展示
- 存储方式：Cloudflare R2

**数据规模**：
- 298 城市 × 4 张/城市 = 约 1200 张图片
- 预计存储空间：约 500MB - 1GB

**数据源**：
| 来源 | 优点 | 缺点 | 建议 |
|-----|------|------|-----|
| Unsplash API | 免费商用、高质量 | 中国城市图片较少 | 适合知名城市 |
| Pexels API | 免费商用、高质量 | 中国城市图片较少 | 备选 |
| 百度图片 | 中国城市图片多 | 需要爬虫、版权问题 | 主要来源 |
| 必应图片 | 质量较好 | 需要爬虫 | 备选 |

**实施方案**：
使用用户提供的 `image_downloader.py` 工具：
```bash
# 示例：爬取大理市图片
python image_downloader.py "大理市风景" --engine Baidu --max-number 10 --output ./images/dali
```

### 2.2 用户评价数据（重点）

**需求描述**：
- 真实用户对城市的居住体验评价
- 包含：评分（1-5星）、评价内容、评价时间、评价维度
- 评价维度：生活成本、空气质量、医疗、交通、安全、宜居感受等

**数据规模**：
- 目标：每城市 5-20 条评价
- 总计：约 3000-6000 条评价

**数据源分析**：

| 来源 | 数据类型 | 数据量 | 难度 | 建议 |
|-----|---------|-------|------|-----|
| **大众点评** | 城市/景点评价 | 丰富 | 中 | ⭐ 推荐 |
| **马蜂窝** | 旅居/旅游体验 | 丰富 | 中 | ⭐ 推荐 |
| **小红书** | 生活体验分享 | 非常丰富 | 高（反爬严格）| 质量最好 |
| **知乎** | 城市生活问答 | 中等 | 低 | 深度内容 |
| **豆瓣小组** | 城市生活讨论 | 中等 | 低 | 真实体验 |
| **贴吧** | 城市讨论 | 丰富 | 低 | 本地视角 |
| **微博** | 城市话题 | 丰富 | 中 | 时效性强 |

**评价数据结构**：
```javascript
{
  city_id: 123,
  city_name: "大理市",
  source: "马蜂窝",           // 数据来源
  source_url: "https://...",  // 原始链接

  content: "在大理生活了三个月...", // 评价内容
  publish_date: "2024-06-15",  // 发布时间

  // 细分评分（如果有）
  cost_rating: 5,      // 生活成本评分

  medical_rating: 3,   // 医疗评分

  safety_rating: 4,    // 安全评分

  // 标签

  // 元数据

```

**关键词策略**：
```

"{城市名}适合养老吗"
"{城市名}定居感受"
"{城市名}居住体验"

# 宜居评价类
"{城市名}宜居吗"
"{城市名}适合定居吗"
"{城市名}生活怎么样"
"在{城市名}生活是什么体验"

# 特定人群
```

## 四、实施计划

### 4.1 阶段划分

| 阶段 | 内容 | 周期 | 产出 |
|-----|------|------|------|
| **Phase 1** | 图片爬取 | 3天 | 1200+张城市图片 |
| **Phase 2** | 用户评价爬取 | 5天 | 3000+条评价 |
| **Phase 3** | 基础数据补全 | 2天 | 人口/GDP/面积 |
| **Phase 4** | 房价租金更新 | 2天 | 租金/房价数据 |
| **Phase 5** | 数据清洗入库 | 2天 | 数据质量检查 |

### 4.2 Phase 1: 图片爬取（详细）

**Step 1**: 准备城市关键词列表
```python
# 生成搜索关键词
keywords = [
    "{城市名}风景",
    "{城市名}城市",
    "{城市名}地标",
    "{城市名}旅游"
]
```

**Step 2**: 使用 image_downloader.py 批量爬取
```bash
# 批量执行脚本
for city in cities:
    python image_downloader.py "{city}风景" \
        --engine Baidu \
        --max-number 10 \
        --output ./raw_images/{city}
```

**Step 3**: 图片筛选与处理
- 去除低质量图片（模糊、水印明显）
- 统一尺寸处理
- 压缩优化

**Step 4**: 上传到 R2 并更新数据库
```javascript
// 上传并记录到 city_images 表
await uploadToR2(imagePath)
await db.run('INSERT INTO city_images ...')
```

### 4.3 Phase 2: 用户评价爬取（详细）

**目标平台优先级**：
1. 马蜂窝（旅居体验，结构化好）
2. 知乎（深度内容，易爬取）
3. 大众点评（评分体系完善）
4. 豆瓣小组（真实讨论）

**数据清洗规则**：
- 过滤广告内容
- 去除重复评价
- 内容长度 >= 50 字
- 时间范围：近2年内
- 敏感词过滤

## 五、数据库扩展

### 5.1 新增表：crawled_reviews（爬取的评价）

```sql
CREATE TABLE crawled_reviews (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  city_id INTEGER NOT NULL,
  source VARCHAR(50),        -- 数据来源：mafengwo/zhihu/dianping
  source_url VARCHAR(500),   -- 原始链接
  author VARCHAR(100),       -- 作者昵称
  rating DECIMAL(2,1),       -- 评分 1-5
  content TEXT,              -- 评价内容
  publish_date DATE,         -- 原始发布时间

  -- 细分评分
  cost_rating DECIMAL(2,1),
  air_rating DECIMAL(2,1),
  medical_rating DECIMAL(2,1),
  traffic_rating DECIMAL(2,1),
  safety_rating DECIMAL(2,1),

  tags TEXT,                 -- JSON数组
  likes_count INTEGER DEFAULT 0,

  -- 审核状态
  status VARCHAR(20) DEFAULT 'pending', -- pending/approved/rejected

  crawled_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (city_id) REFERENCES cities(id)
);
```

## 六、合规与风险

### 6.1 法律合规
- 遵守 robots.txt 协议
- 不爬取个人隐私信息
- 用户昵称脱敏处理
- 注明数据来源
- 控制爬取频率，不影响目标站点

### 6.2 数据质量风险
- 评价内容可能有虚假信息
- 图片可能有版权问题
- 数据时效性问题

### 6.3 应对措施
- 人工审核机制
- 优先使用无版权图片（Unsplash/Pexels）
- 定期更新数据
